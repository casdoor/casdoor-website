Casdoor is an open-source [identity and access management (IAM)](https://en.wikipedia.org/wiki/Identity_management) and [single sign-on (SSO)](https://en.wikipedia.org/wiki/Single_sign-on) platform. Your applications send users to Casdoor to sign in, and Casdoor gives them back a verified identity over OAuth 2.0, OpenID Connect, SAML, or CAS. Everything, from users and applications to sign-in pages and providers, is managed in a web console.

## What Casdoor does

- **Single sign-on for your applications.** Casdoor is an [OAuth 2.0 and OIDC](/docs/how-to-connect/oauth) provider, a [SAML](/docs/how-to-connect/saml/overview) identity provider, and a [CAS](/docs/how-to-connect/cas) server. It also serves [LDAP](/docs/ldap/ldapserver) and [RADIUS](/docs/radius/overview) for applications, VPNs, and network devices that only speak those protocols.
- **Sign-in with existing accounts.** More than 70 [OAuth providers](/docs/provider/oauth/overview) are built in, from Google, GitHub, and Microsoft to WeChat, DingTalk, and Lark, plus any SAML or OIDC identity provider.
- **Strong authentication.** Passwords, email and SMS codes, [WebAuthn and passkeys](/docs/how-to-connect/webauthn), [TOTP](/docs/how-to-connect/totp-authenticator-app), and [multi-factor authentication](/docs/user/multi-factor-authentication) that an organization can make optional or required.
- **Users and organizations.** Several [organizations](/docs/organization/overview) can share one Casdoor, each with its own users, groups, roles, applications, and branding. Users can be imported and kept in sync from LDAP, Active Directory, Keycloak, Okta, and other systems with [syncers](/docs/syncer/overview), or provisioned over [SCIM](/docs/scim/overview).
- **Authorization.** Casdoor has [permissions](/docs/permission/overview) built on [Casbin](https://casbin.apache.org/), with ACL, RBAC, and ABAC models, and an API your services can call to check them.
- **Sign-in pages without code.** Each application's sign-in and sign-up pages, fields, and providers are configured in the console. See [UI customization](/docs/application/ui-customization).
- **AI agents.** Casdoor exposes its management API as an [MCP server](/docs/how-to-connect/mcp/overview) and acts as an [OAuth 2.1 authorization server for MCP servers](/docs/mcp-auth/overview).
- **Operations.** One Go binary and a SQL database (MySQL, PostgreSQL, SQL Server, Oracle, SQLite, and others). The console is available in 11 languages.

## How sign-in works

Casdoor uses the standard OAuth 2.0 authorization code flow. In most cases a [Casdoor SDK](/docs/how-to-connect/sdk) or any OIDC library handles these steps for you.

![How Casdoor works](/img/principles.gif)

1. **Your application sends the user to Casdoor.** It redirects the browser to the authorization endpoint:

   ```text
   https://<casdoor-host>/login/oauth/authorize?client_id=<client-id>&response_type=code&redirect_uri=<callback-url>&scope=openid%20profile%20email&state=<random-value>
   ```

   - `client_id`: the **Client ID** of the [application](/docs/application/overview) in Casdoor.
   - `redirect_uri`: your application's callback URL. It must be listed in the application's **Redirect URLs**.
   - `state`: a random value your application generates and checks when the user comes back, to protect against cross-site request forgery.

2. **The user signs in.** Casdoor shows the sign-in page of that application. The user enters a password, uses a passkey, or picks a provider such as Google or GitHub.

3. **Casdoor sends the user back with a code.** The browser is redirected to `redirect_uri` with a one-time `code` and the same `state`.

4. **Your application exchanges the code for tokens.** Your backend calls `https://<casdoor-host>/api/login/oauth/access_token` with the code and the application's **Client secret**, and receives an access token, an ID token, and a refresh token.

5. **Your application uses the tokens.** The ID token is a JWT that identifies the user. The access token authorizes calls to Casdoor's APIs, such as `/api/userinfo`, and to your own resource servers.

![OAuth 2.0 authorization code flow](/img/oauth.png)

For the details of each request, see [OAuth 2.0](/docs/how-to-connect/oauth) and [OIDC client](/docs/how-to-connect/oidc-client).

## Online demo

- [Casdoor demo](https://door.casdoor.com/): sign in as the global administrator with user name `admin` and password `123`.
- [Casbin-OA](https://oa.casbin.com) ([source code](https://github.com/casbin/casbin-oa)): a Casbin web application that signs users in with Casdoor.
- [Casnode](https://casnode.org) ([source code](https://github.com/casbin/casnode)): the Casbin community forum, which uses Casdoor for accounts and sign-in.
